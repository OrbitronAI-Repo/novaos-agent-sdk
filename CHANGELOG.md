# Changelog

## [Unreleased]

## [2.3.1] - 2026-11-17

### Added
- A new guide, *Steps that need a person*, lists the steps that need someone in a web browser (sign-in, admin approval of a new version, installing from the web UI), who does each and on which marketplace page, and when the approval policy skips the admin step. It also sets out how a coding assistant should behave at those steps: stop and say who must act and where, never claim an agent is live or invent an instance ID, never try to approve its own agent, check for itself once the person says it's done, and offer browser help only with the person's consent for each action. *Installing and running a published agent* links to it.
- A new guide, *Installing and running a published agent*, lists the six interim calls that install your own copy of a published agent, find it, run it and read its answer: the public Agent Card, `POST /api/instances` on the marketplace (with the `X-Requested-With` header it requires), `GET /api/v1/instances`, `POST /api/v1/execute` with `X-Idempotency-Key`, `GET /api/v1/runs/<run-id>` and its `/events`, where the answer is the `message.final` event. It also shows the same run from `GatewayClient` with an idempotency key, and the CLI commands to use when a run fails. The calls are marked interim until the CLI has its own commands.

### Fixed
- `AGENT_GUIDE.md` and `llms.txt`, shipped in the package, linked to two guides that were not on the documentation site yet (*Installing and running a published agent* and *Steps that need a person*); both are now published. The guide also said `publish-status --wait` needs `novaos-cli` 2.3.0 or later; it needs 2.2.0 or later.

## [2.3.0] - 2026-11-16

### Added
- `ConnectorTool.call_mcp_tool()` (`ctx.tools.connectors.call_mcp_tool("<publisher>.<server>.<tool>", args)`) calls a tool on an MCP server the agent declares in its manifest, through the same MCP Gateway path as the other bindings and without the "bypassing the governed surface" warning that `call_ungoverned_tool()` logs. A platform tool (`novaos.*`) or a name that is not `<publisher>.<server>.<tool>` raises `ValueError` before any request is sent.
- `KnowledgeTool.search()` gains `collection_ids` (search several collections in one call, ranked together) and `scope` (`"tenant_visible"` searches every collection the caller can read). Hits carry `metadata.collection_id`; if one collection fails to search the call still returns the others' hits with `degraded` set. `collection_ids` cannot be combined with `scope="tenant_visible"`, and an empty list or unknown `scope` raises `ValueError` before any request is sent. Omitted, requests are unchanged.
- `ctx.in_run_check` exposes the in-run check configuration the platform resolved for the run: the judge model, each rubric's `id`, `version`, `text` and `threshold` (the bar it must meet), and optional `max_refinements`, `budget_ms`, `deterministic` and `regulated_outputs`. It is read only from the platform's `in_run_check` context key, is immutable, and no environment variable or skill argument can supply or change it. It is `None` when the platform attached none, and a malformed configuration also gives `None` rather than a partial check.
- `novaos_client_sdk.evaluation.rubrics`: `parse_rubric()` reads a rubric file (YAML front matter plus a numbered body, Unix or Windows line endings) and rejects malformed or oversized files (file over 100000 characters, body over 8000, a case field over 2000, more than 20 criteria, 200 cases or 20 contexts per case, duplicate criterion IDs, unknown fields such as an output format). `rubric_json_schema()` returns the JSON Schema the platform publishes (a byte-identical copy ships in the package). `calibrate_rubric()` scores a rubric's labelled good and bad cases with a judge callable, so an always-pass or always-fail judge fails calibration; a judge score that is not a number from 0 to 1 raises `ValueError` instead of counting as a verdict. The SDK ships no built-in rubrics. The `evaluation` extra now also installs `jsonschema` and `pyyaml`.
- `novaos_client_sdk.checkpoint`: a save/resume interface so an agent loop, with or without LangGraph, can store its state outside the pod and continue it later. `SaveResume` has `save`, `put_pending_writes`, `load`, `list`, `pause`, `resume`, `committed_writes`, `flush` and `close`; `CheckpointSaveResume` implements it over the checkpoint service's HTTP API. The task of every call is the execution token's `run_id`, so a re-minted token resumes the same task, and a `task_id` argument that names another task raises `CheckpointIdentityError`. At most one save is in flight; `write_after_save` stores a checkpoint with `Durability.SYNC` before it runs a write, and while the service is unavailable it waits on capacity for up to five minutes, then raises `CheckpointUnavailable` without writing. The resume lease is renewed every 20 seconds, and `close` repeats the lease epoch (`LeaseLost` is raised, not swallowed). A reader loads its own checkpoint format and the one before; any other raises `UnsupportedCheckpointFormat`. `Durability.EXIT` is refused for tasks with write tools. The interface needs no extra. `CHECKPOINT_SERVICE_URL` names the service and `MCP_GATEWAY_URL` the tool gateway for `committed_writes`.
- `NovaCheckpointSaver`, LangGraph's checkpointer on that interface, installed with the new `agent-loop` extra (`pip install novaos-agent-sdk[agent-loop]`). `interrupt()` and `Command(resume=...)` work through it, including in subgraphs. Each save carries all channel values; large values are not yet stored once by hash.
- `AgentLoop` (`novaos_client_sdk.agent_loop`, `agent-loop` extra): a model-and-tools loop on LangGraph that stops within set limits and says why. Limits on steps (model calls), tool calls, tokens, wall time and plan revisions default to 8, 12, 60,000, 240 s and 3, with platform caps of 50, 100, 500,000, 1,800 s and 10; a value above its cap raises `ValueError`, and limits are never read from the environment. Every stop has one `StopReason`: `done`, `limit_reached` (with `limit` naming it), `stalled`, `cancelled` or `failed`. A pause for a person returns `input-required` (`stop_reason` is `None`) and continues with `resume()`. A tool call that already succeeded with the same arguments is skipped (a failed call can be retried) and the second skip stops the run as `stalled`; read-only tools declared `repeatable` are exempt within the step limit. Write calls carry an idempotency key built from the business key, the step and the write's position among that step's writes, never the run (a retry of a write that failed sends the same key), and a loop with write tools requires `business_key`. A cancel stops at the next safe point, starts no further tool call, records `cancelled` in a final checkpoint and returns the partial result. Each node emits an `agent_loop.step` event and an `agent_loop.<node>` span with the task id. The checkpointer is any LangGraph checkpointer (in-memory by default, or `NovaCheckpointSaver`); the default in-memory saver forgets a task once its run stops and keeps at most 1,000 paused tasks. On a paused task, `run_in()` takes the next message as the answer and resumes; if the saved state cannot be read it returns `failed` instead of starting over. An error outside the nodes (checkpointer, `emit`, a custom node) ends the run as `failed`. Runs of one task do not overlap in a process, even across `AgentLoop` objects. `loop.graph` exposes the `StateGraph`; `result.to_skill_result()` maps the outcome to a `SkillResult`.
- `ContextLayer` for `AgentLoop(context=...)`: every model call gets a prompt built in a fixed order (system text, summary of older turns, recalled memories, conversation) within a token budget (`prompt_tokens`, default 24,000; an estimate, not a tokenizer count). Older turns over the budget are folded into a summary, not dropped (`ExtractiveSummarizer`, or your own `Summarizer`), then the lowest-ranked memories are trimmed. The budget counts the tool definitions sent with each call. Memory is read live through `MemoryReader` (`MemoryClientReader` uses the turn's pre-fetched context for its first read, else `assemble_context` with the run's `memory_budget`) on every run and every resume; it is read-only, a failed or slow read (`memory_timeout_s`, default 5 s, never beyond the run's wall time) means no memory, and a checkpoint keeps only the ids and versions read (`memory_reads`, added when they change), never the content. Re-reads of saved results are not counted against the tool-call limit. `prompt_tokens` may not exceed `PLATFORM_MAX_PROMPT_TOKENS` (150,000 estimated tokens, the gateway's default 500,000-character cap on message text); `max_prompt_tokens` raises it for a gateway that allows more. The summary of older turns is marked as data (`<summary>` tags), like memories. `MemoryNamespace.context_query` records what the pre-fetch asked, and `MemoryClientReader` reuses the pre-fetch only for the same question. When the LLM Gateway refuses a prompt as too large (the model's input limit, `input_too_long`, or a request above the tenant's tokens-per-minute limit), the loop builds a smaller prompt and asks again, up to three times, and keeps the smaller budget for the run; other refusals (guardrails, budgets) are not retried. `size_rejection()` reads such a refusal. One long turn of large tool results is kept within the budget by shortening its older results in the prompt (the state keeps them whole). `MemoryClientReader` takes the platform's `memory_budget` token budget as the limit on recalled memory, and `LoopResult.to_skill_result()` carries the summary in `metadata["summary"]`. Results of read-only tools are used again on resume except those holding an authoritative field (`rating`, `verdict`, personal data) or older than 24 hours, which are fetched again under a replaceable `ReusePolicy`. `LoopResult.summary` and `run(summary=...)` carry the summary of older turns; `keep_summary=False` leaves none in the checkpoint. Without `context` nothing changes.
- `call_llm_judge()` now uses the default judge model the LLM Gateway serves when the caller passes no model and `NOVAOS_JUDGE_MODEL` is unset, before falling back to `gpt-4o-mini`. It reads `llm_judge` / `default_model` from the open `GET /gateway/defaults` (no token; the response is `{"defaults": {namespace: {key: value}}}`, the platform defaults). The result, a failed lookup included, is cached per gateway URL for 60 seconds, so a slow or down gateway costs one 3 s wait a minute, not one per judge call; a gateway that is unreachable, older, or has no default behaves as before. A blank `NOVAOS_JUDGE_MODEL` is now treated as unset instead of being sent as an empty model name. `fetch_gateway_judge_default()` is the lookup.
- `call_pinned_judge()` (in `novaos_client_sdk.evaluation.graders`) makes a judge call to a model the caller passes, with no default and no `NOVAOS_JUDGE_MODEL` lookup, so a pod cannot switch the judge model through its environment. An empty model raises `ValueError` before any request is sent. It sends the same `novaos_eval_judge` tag as `call_llm_judge()`. The tag is set by the client, so it lets the LLM Gateway catch a mistaken call; it is not an access control. `call_llm_judge()` is unchanged and keeps the `NOVAOS_JUDGE_MODEL` fallback for offline evaluation.
- `GatewayClient.execute()` takes an optional keyword-only `skill` argument that chooses which of an agent's skills runs, for example `skill="ask"`. It is sent only when you set it. An agent with a single skill needs no selector; calling an agent that has more than one skill without `skill` is not guessed for you: `execute()` still returns a `run_id`, and the run then ends as failed with an explicit error.
- `ctx.tools` can key writes from the business key and a step instead of the execution key, with the same function AgentLoop uses (`novaos_client_sdk.write_keys.idempotency_key`, still importable from `novaos_client_sdk.agent_loop`). It is off by default: call `ctx.tools.set_business_key(...)` and `ctx.tools.set_business_key_idempotency(True)`. The key is then the same after a resume or a continuation that reaches the same step on the same record. `ctx.tools.set_step(n)` names the step (default 0) and restarts the write counter; the counter counts writes only, across every binding, and a key passed in explicitly is sent unchanged and does not advance it. Without a business key the execution-scoped key is sent as before, which protects redelivery of one execution only; the first such keyed write of an execution logs a warning and `ctx.tools.writes_without_business_key` counts them. Nothing raises. Do not turn the switch on until mcp-gateway caches only completed successful replies: today a continuation's write with the same key would be answered with the cached approval request.
- `ctx.tools` sends an `X-Idempotency-Key` header on each tool call and, when a business key is set, `X-NovaOS-Business-Key`. The key is derived from `ctx.idempotency_key`, the tool, its arguments and how many times that exact call already ran, so a redelivered execution repeats a write's key while a repeated read or poll gets a new one. Without an `idempotency_key` from the platform no header is sent, as before. `MCPClient.tools_call()` takes `idempotency_key` and `business_key` for the same headers.
- `citations_resolve`, a built-in deterministic check for the in-run check: it fails when a `[n]` marker in the answer has no n-th entry (from 1) in the run's tool results. Only the `[n]` form counts (code spans and fenced blocks are skipped), and an answer with no markers holds. A check registered under that name replaces it.
- `AgentLoop(check=InRunCheck(config, judge, checks=...))` checks the final answer before the loop returns it. Registered deterministic checks run first (`output_schema()` wraps a validator) and a failed one skips the judge; a name with no registered check counts as failed. Each rubric is then scored by a `JudgeClient` (`GatewayJudge` calls the LLM Gateway with the judge tag, on the rubric's pinned model, with the instructions the platform calibrates rubrics with and the run's tool results as `contexts`) whose reply is parsed strictly: one score from 0 to 1 for exactly the rubric's criteria, the answer scoring as the lowest, else `JudgeRejected`. A failed rubric with budget left and no write in the run gets one corrective pass on the same model with no tools, built from the published criterion text (never the judge's words), and the better-scoring answer is kept; after a write, or with `max_refinements` 0, the answer is only scored. A judge error, timeout (`budget_ms`) or unparseable reply keeps the draft and records `judge_error`. An answer with a field named in `regulated_outputs` (found at any depth; text that is not a JSON object is assumed to carry all of them) is never passed on a judge score alone: it needs a passing deterministic check that covers the field (`InRunCheck(covers=...)`), else the result is `failed_kept_draft`. `budget_ms` bounds the whole check. A run that ends before its answer is checked records `not_run`. The record (`ran`, `kind`, `result`, `deterministic` (one `check`/`passed` entry per check that ran), `rubrics` with `ref`/`score`/`threshold`/`failed_criteria`, `judge_model`, `judge_model_version`) is `LoopResult.in_run_check`, `metadata["in_run_check"]` on the skill result, and on the check node's step event; the judge's reasoning (capped at 500 characters, PII-masked) goes only to the check node's span. Without `check` nothing changes.
- `call_pinned_judge_reply()` is `call_pinned_judge()` returning the model version the gateway reports (`PinnedJudgeReply`) with the text.
- `AgentLoop.run_in` sends a pause as a write confirmation when the model's `input_request` has a `question`, a `call_id` and a `tool_name` that match a write call (a tool that is not read-only) the model issued in the same turn, so the platform resumes it on the same run and the saved state is found. Before, an agent had to send that message itself; a loop's plain pause started a new run on the answer and asked its question again. A `call_id` or `tool_name` that matches no write call of the turn gives a plain pause and a log warning. `LoopResult.approval` is the `(question, call_id, tool_name)` of an approval pause (else `None`), `approval_request()` and `approval_fields()` (`novaos_client_sdk.agent_loop.result`) are the checks, and `to_skill_result()` returns the question as the output of an approval pause. A pause without all three fields, or a context without `task_updater`, behaves as before. An approval pause is resumed only by the platform's decision (`{"type": "hitl_response", "action_id": ..., "approved": ...}`; `approve`, `confirm` and `retry` approve): a re-sent or retried message leaves the run paused and sends the pause again, and a rejection resumes the run and the loop refuses that write call with the same arguments (`error: the person rejected this write; it was not made`). `parse_decision()` reads a decision. A plain pause is still answered by any next message.
- The `agent_loop.<node>` step spans and the `mcp.<method>` spans carry `plan_id`, so a trace can be found by plan across the platform and the agent. The id is the `plan_id` claim of the run's execution token, bound with the run (`RunContext.plan_id`); `mcp.<method>` spans also carry `novaos.task_id`. A run no plan started has no such claim, and the attribute is then left off, not set empty. A claim that is not a short opaque id is dropped. Ids only, no text.
- `@agent.skill(..., examples=[...])` sets `AgentSkill.examples` on the card `to_agent_card()` builds, so a caller can read the input format a skill expects from the served Agent Card. The building-an-agent guide documents it, and warns that an agent image pinned to SDK 2.3.0rc6 or earlier fails at startup with `examples=`.
- README: a "Build, publish and run on NovaOS" section covering `novaos-cli` (install, environment, sign-in, `init`, `publish`, `publish-status`), what happens after a publish, and the import name `novaos_client_sdk`. The package metadata links the CLI's npm page (`CLI` under `project.urls`).
- `AGENT_GUIDE.md` and `llms.txt` ship in the wheel and sdist, inside the installed `novaos_client_sdk` directory, so a coding assistant that has only the installed package finds a guide. The guide covers the `novaos-cli` lifecycle (`init`, `test`, `manifest validate`, `publish --dry-run`, `publish`, `publish-status --wait`), one table of the SDK's and the CLI's environment variables saying which tool reads each, the interim calls to install and run a published agent, and the steps that need a person. `llms.txt` indexes it and the docs pages. The README says how to print the guide's path.
- `baml` extra (`pip install "novaos-agent-sdk[baml]"`) installs `baml-py`, which `novaos_client_sdk.baml_helpers` needs; it is also part of `all`.
- `MemoryClient` warns before a scope's write quota is full. It reads `meta.quota` from every `memory.write` reply and logs a warning when the space left is 10% of the limit or less (`quota_warning_threshold`, default `0.1`; `0` turns it off), at most once a minute per scope. The warning says a durable quota (user, agent, tenant) has no reset: it counts stored memories, so space comes back only when memories are deleted or the tenant's limit is raised. An optional `on_quota_low` callback receives a `QuotaStatus` (`scope`, `remaining`, `limit`, `reset_at`) on every such write; an exception it raises is logged and never fails the write. `MemoryClient.last_quota` holds the latest `QuotaStatus` per scope. A reply with no or malformed `meta.quota` is ignored.

### Changed
- OpenTelemetry (`opentelemetry-api`, `opentelemetry-sdk` and the OTLP/HTTP exporter) is now installed by default, so an agent exports spans when `OTEL_EXPORTER_OTLP_ENDPOINT` is set without installing an extra. This adds those packages and their own dependencies (`protobuf`, `requests`) to every install. `pip install novaos-agent-sdk[otel]` still works and is now a no-op.
- `ExecutionContext.require_token()`, `to_auth_headers()`, `to_context_headers()` and the `ctx.tools` bindings now use the run's newest execution token when `NOVAOS_TOKEN_ENDPOINT` points at the auth-proxy's token endpoint (for example `http://127.0.0.1:8002`). A run that outlives the token it was started with keeps calling the platform with a valid one. The proxy is asked only once less than a third of the held token's lifetime remains, and any failure falls back to the token already held. Without the variable nothing changes.
- `CheckpointSaveResume.from_context` names its environment variable in `CHECKPOINT_SERVICE_URL_ENV` (`novaos_client_sdk.checkpoint.save_resume`), like the other service clients. The variable, the lookup order (`base_url`, then the environment) and the error text are unchanged.
- The public docs, README, SECURITY page and examples no longer use the word ACP outside the 1.x migration pages, and shipped docstrings no longer cite internal decision-record or knowledge-base references. The export guard rejects those references from now on.

### Fixed
- `ctx.get_secret()` now reads the environment variable named for the secret when no sealed value was delivered for it (previously it reported that no secret was available when the value was set as an environment variable). A sealed value still wins, and a sealed value that fails to open is never replaced. `ctx.secret_names` also lists the names in the `NOVAOS_SECRET_NAMES` environment variable that are set.
- The `skill.<name>` span now joins the run's trace: it is started as a child of the inbound `traceparent` instead of a new root trace, so spans a skill starts nest under it. Without a `traceparent`, or without the `[otel]` extra, nothing changes.
- Spans buffered by the batch exporter are flushed, with a short bounded wait, before a skill's response is returned, so the last spans are no longer lost when the process exits right after the response.
- `LLMClient` now sends a W3C `traceparent` and records each gateway call as a client span (`llm.chat.completions`, `llm.embeddings`, ...), so model calls appear in the run's trace with the gateway's own spans beneath them. The span ends when the response body is closed, which covers streamed completions.
- `get_agent_logger()` and `ctx.logger` now include `trace_id` and `instance_id` on every line, so agent logs join the run's trace without agent code adding them. `get_agent_logger()` gains optional `trace_id` and `instance_id` arguments.
- When tracing is requested through `OTEL_EXPORTER_OTLP_ENDPOINT` but the OpenTelemetry packages are missing, a single warning now names the missing `novaos-agent-sdk[otel]` extra.
- Judge calls (`call_llm_judge()`) no longer send `turn_off_message_logging` in the request metadata. The LLM Gateway refuses that field in a request body with a 401, so judge calls failed against a real gateway. The Gateway already keeps message logging off for every request.
- `MCPClient` and `MemoryClient` now accept `headers` as a callable as well as a mapping. A callable is read for every request, so `MCPClient(headers=ctx.to_auth_headers)` (without the call) keeps sending the run's newest execution token on a client that lives longer than the token. A mapping is still read once, when the client is built, so a client built from `ctx.to_auth_headers()` keeps the token it was built with. The documentation examples now pass the callable, and `ctx.memory.client()` builds its `MemoryClient` from it, so a client created that way follows the run's newest token.
- `MemoryClient` no longer retries a write the Memory Service refused because a quota is full. A 429 whose error is `QUOTA_EXCEEDED` is raised at once as the new `NovaOSQuotaExceededError` (`error_code`, `status_code` 429, `is_retryable` `False`) instead of making three attempts with backoff on every call. It subclasses `NovaOSServerError`, so existing `except NovaOSServerError` handlers still catch it. A plain rate limit (`RATE_LIMIT_EXCEEDED`, or a 429 with no error code) is still retried with `Retry-After`. A full quota also no longer counts as a failure for the circuit breaker, so it cannot make reads fail fast.
- A skill run through `SendStreamingMessage` (how conversation runs arrive) now has a `skill.<name>` span, as `SendMessage` already did: a child of the inbound `traceparent`, the parent of the spans the skill starts, `ERROR` when the skill raises or returns `FAILED`, and flushed before the stream ends. On both paths the span now lasts as long as the skill, including a skill that keeps running after its caller disconnected.
- `MCPClient` now sends a `traceparent` on every request, so MCP Gateway calls join the run's trace instead of starting their own. Each request is an `mcp.<method>` client span (`mcp.tools/call`, ...). The new keyword-only `execution_context` argument supplies the run's `traceparent` for calls made outside the skill's span; without it, the current run's is used. Without OpenTelemetry that `traceparent` is sent as is.
- `ctx.tools` calls now send the `tool.<name>` span's own `traceparent` when it is in the run's trace, so the MCP Gateway's spans are children of the tool span instead of its siblings. A tool span in another trace still sends the per-request `traceparent`.
- The traceback of a skill that raises is now logged through `ctx.logger` as one JSON line with `run_id`, `trace_id`, `span_id`, `agent_id`, `tenant_id`, `instance_id` and `exc_info` (PII masked), so it appears under `agent logs --run-id`. It was a plain-text line with no run id, and with `mask_output_pii` it had no traceback at all.
- Log lines from the SDK's own modules and from third-party libraries now carry the run's ids while a skill runs. When an agent runs its first skill the root logger gets a JSON stdout handler that adds `run_id`, `trace_id`, `span_id`, `agent_id`, `tenant_id`, `instance_id` and `logger` to each line; its level is not changed. It is not installed when the application configured the root logger itself (add `novaos_client_sdk.logging.RunContextFilter` to your handler instead) or when `NOVAOS_STRUCTURED_ROOT_LOGS=false`. `ctx.logger` lines are not duplicated and now include `span_id`. `print()` output is not covered: use `ctx.logger`.
- A skill that pauses its own task with `ctx.task_updater.requires_input()` or `requires_auth()` and returns the matching `WAITING_USER` or `AUTH_REQUIRED` status now keeps its own pause message. Before, the SDK replaced it with one rebuilt from the skill's output, which dropped the approval details the platform reads from it, so a gated write could not be approved.
- The exported wheel and sdist now include `rubric.schema.json`: the public export allowlist and `MANIFEST.in` skipped JSON, so `parse_rubric()` and `rubric_json_schema()` raised `FileNotFoundError` from an installed package.
- `call_pinned_judge_reply` and `PinnedJudgeReply` are importable from `novaos_client_sdk.evaluation.graders`.
- `httpcore` is declared as a dependency; the SSRF guard imports it directly.
- `AgentLoop.run_in()` takes the task's resume lease before it continues a cut-off run, where before the first step ran a write and only then failed on the held lease, so a retry while the old pod's lease was live repeated the write on every attempt. A held lease is retried every `lease_retry_s` (5 s) for up to `lease_wait_s` (default: the checkpointer's lease life plus 15 s, 75 s for the default 60 s lease) before the run returns `failed` (`LeaseConflict`) with no step run, so a replacement pod continues the run once a killed pod's lease has expired. Any other lease error fails at once, and a cancel during the wait returns `cancelled` without writing a checkpoint, because the lease is not held. `NovaCheckpointSaver.aacquire()` and `CheckpointSaveResume.acquire()` take the lease on request.
- `AgentLoop.run_in()` continues a run whose pod died mid-way from its last checkpoint, where before it started the task over from the first step and repeated the model turns and tool calls already made. A run is continued only when the checkpoint has steps left and no stop was recorded, so a finished, cancelled or failed task still starts a new run, and the new message is not used when a run is continued. Both savers behave the same.
- `GatewayJudge(...)` raises `NovaOSError` naming `pip install novaos-agent-sdk[llm]` when `openai` is not installed, where before the first judge call failed inside the in-run check and every run recorded `judge_error`.
- `AgentLoop.run_in()` waits out a killed pod's resume lease when it takes an approval's decision or a person's answer for a paused task, as it already did for a cut-off run. Before, a replacement pod that took the answer right after a kill got `LeaseConflict` at once and the run returned `failed` (and the workflow does not retry a failure the agent reports). It now retries every `lease_retry_s` for up to `lease_wait_s` (the checkpointer's lease life plus 15 s, 75 s by default), then returns `failed` with no step run; a cancel during the wait returns `cancelled`. A message that is not a decision leaves an approval pause as it is and takes no lease.

### Documentation
- The RAG reference no longer says `search()` with no `collection` searches all collections: the service needs a collection, `collection_ids` or `scope="tenant_visible"`. It now documents all three.

## [2.1.0] - 2026-10-15

### Added
- `GatewayClient.execute()` gains an optional `attachments` parameter: a list of the new `Attachment` objects (`type`, plus exactly one of `url` or raw `data` (`bytes`, `bytearray` or `memoryview`), and an optional plain-filename `name`) sent as `attachments` in the `POST /api/v1/execute` body. `data` is base64-encoded by the SDK. Invalid attachments raise `NovaOSError` before any request is made. Omitted or empty, the request body is unchanged.
- `AgentCatalogClient` and `CatalogAgent` (`novaos_client_sdk.catalog`) — find published agents through the marketplace's public catalog (`GET /api/agents`) by the skills their Agent Card declares, with `skill_match="all"` or `"any"`. This is the external counterpart to Agent-DNS, which is cluster-internal and carries no capabilities. Results follow the catalog's cursor, stop if the cursor does not advance, and map HTTP failures onto the SDK's exception hierarchy. `CatalogAgent.gateway_url()` and `.card_url()` give the gateway addresses to call an agent and read its card.
- `AgentExecutionContext.custom_headers` — the caller's custom request headers, filtered and lower-cased. Every `ctx.tools.*` call now forwards them to the MCP Gateway; headers the SDK sets itself (`Authorization`, `X-Tenant-ID`, ...) always take precedence. New `novaos_client_sdk.header_safety` module (`is_safe_custom_header_name`, `filter_custom_headers`) applies the platform's header-name rules.
- `MemoryClient.update()` and `ctx.tools.memory.update()` — edit one of the agent's own `agent`-scope memories in place, using the `version` read from `query`. Returns the new `UpdateResult`.
- `MemoryClient.hint_status()` and `ctx.tools.memory.hint_status()` read the outcome of a submitted hint (new `HintStatus`); `ctx.tools.memory.proposal_status()` reads the outcome of a proposed write.
- Optional `memory_type` (`semantic`, `episodic`, `procedural`) on memory `write`, `query` and `assemble_context`, and optional `conversation_id` on `query` and `assemble_context`, to filter recall by type or conversation. Omitted, requests are unchanged. `MemoryType` is exported and `MemoryMetadata` gains `memory_type`.
- `MemoryClient.write()` gains `ttl_seconds` and `classification`; `MemoryClient.query()` gains `token_budget` and `latency_budget_ms`.
- `ctx.tools.memory` now also exposes `forget`, `hint` and `assemble`, and `write`/`query` accept the same extra fields.

### Security
- `AgentDiscoveryService` gains `guard_connect_ips` (and `allow_private_ips`) so the Agent Card fetch itself can refuse a `base_url` that resolves to a private, loopback, link-local or reserved address, and connect to the address it checked. It is off by default so a local `http://localhost:8000` agent keeps working; turn it on when `base_url` comes from a user or other untrusted source, since the request carries the `auth` headers.
- `validate_host_allowed` (the `NOVAOS_ALLOWED_HOSTS` check used for the gateway and JWKS URLs) now compares hostnames in their IDNA wire form, so a Unicode host matches its punycode entry, and a host that cannot be encoded is rejected.
- The JSON-RPC, HTTP+JSON and card-fetch HTTP clients now set `follow_redirects=False` explicitly instead of relying on the httpx default.
- The gRPC transport now connects to the IDNA 2008 (punycode) form of a Unicode agent host, the same form `validate_agent_url` checks. gRPC's resolver does not encode Unicode hosts itself, so an internationalised agent host previously failed to resolve instead of connecting to the validated name. `grpc_channel_factory` receives the same normalised target. A host that cannot be IDNA-encoded is rejected when the transport is created.
- Clients built by `AgentDNSRecord.to_client()`, `AgentDNSClient.get_agent_client()`, `discover_and_connect()` and `AgentDiscoveryService.to_client()` now re-check the address at connect time and connect to the address they checked, closing the gap in which a short-TTL DNS answer could be public for `validate_agent_url` and private for the real connection (DNS rebinding). The host name still drives TLS verification and the `Host` header. This applies to the JSON-RPC and HTTP+JSON transports, and to gRPC unless `grpc_channel_factory` builds the channel, which the SDK cannot pin. A `Client` built directly from a URL is unchanged, so `localhost` still works; it can opt in with the new `guard_connect_ips=True`. Requests routed through an `HTTP(S)_PROXY` environment variable connect to the proxy instead.
- `validate_agent_url` (and so `AgentDNSRecord.to_client` and `AgentDiscoveryService.to_client`) now checks the hostname in the same IDNA 2008 form the HTTP transport connects to. Previously a Unicode host such as `faß.example` was resolved as `fass.example` while httpx dialled `xn--fa-hia.example`, so the private-IP guard could validate one destination and connect to another. Allowlist suffixes are normalised the same way, and a hostname that cannot be IDNA-encoded is rejected. `idna>=3.0` is now a declared dependency.

### Changed
- `GatewayClient` now raises `NovaOSRateLimitError` (with `retry_after` parsed from `Retry-After`) for an HTTP 429 from the gateway, instead of a generic `NovaOSError`. `events_with_reconnect()` treats it as retryable.
- **Breaking:** `AgentDiscoveryService.to_client()` now requires `allowed_host_suffixes` naming the domains the Agent Card's URL may point at. A card is remote input, and the client's `headers`/`auth` are sent to whatever host it names, so a call without an allowlist now raises `NovaOSError` before any request is made. There is no opt-out. The private, loopback and link-local IP block still applies on top of the allowlist. To migrate, pass your deployment's or partner's domains: `await discovery.to_client(allowed_host_suffixes=[".partner.example"])`.

### Fixed
- `ObservabilityClient.get_run_events` no longer fails with HTTP 403 when a user reads their own run. A new `route` argument (`"auto"` by default, `"user"`, `"service"`) selects the endpoint; `"auto"` falls back to the user route on a 403.
- `RunEvent` gains optional `sequence`, `trace_id` and `span_id` (`None` when the platform does not return them).
- A skill that raises an uncaught exception now reports `<type>: <message>` as its failure text instead of `str(exception)` alone, so the exception type reaches the platform and an exception with no message (`TimeoutError()`) no longer yields an empty failure. The exception is also logged with its traceback, except when `mask_output_pii` is on, where the traceback is omitted because it carries the message.
- `NovaOSServerError` messages raised for non-2xx responses from the Memory Service, MCP Gateway, Gateway observability and agent-ops clients now append a short excerpt of the response body (RFC 9457 `errors[].detail`, JSON-RPC `error.message`, a `detail` field, or the first ~300 characters), so the reason a call was rejected is visible. The `... returned HTTP <code>` prefix is unchanged, the httpx documentation link is dropped, and the parsed or raw body is available as `details["response_body"]`.
- A duplicate knowledge upload (identical content already indexed) is reported as a `completed` job whose status carries `duplicate_of`, the original document's id. `KnowledgeTool.poll_until_complete` returns it like any completed job instead of waiting for a `duplicate` status, and `IngestJobStatus` (from `get_ingest_status` and `poll_batch_until_complete`) gains `duplicate_of` and `is_duplicate`.
- `KnowledgeTool.poll_until_complete` and `poll_batch_until_complete` now stop on a `cancelled` ingestion job (its collection was deleted before it finished) instead of polling until the timeout.

### Documentation
- `AgentDiscoveryService` documents passing `allowed_host_suffixes` when connecting to third-party partner agents, and why.
- The memory guide now covers typed memories, conversation recall, which writes need human approval, and the `null` score for run- and task-scope results. The observability note on `trace_id`/`span_id` availability is corrected.

## [2.0.0] - 2026-09-30

**The SDK adopts protocol-per-major versioning: `1.x` lines track ACP, `2.x` lines track A2A.** The A2A wire protocol itself already replaced ACP outright in an earlier `0.x` release — `AgentBuilder`/`Client` rewritten onto A2A v1.0.0 JSON-RPC, `handle_acp_request` and every ACP-shaped type removed, with no compatibility shim — and this line has shipped nothing but A2A since. `2.0.0` draws the major-version boundary under that work and folds in everything accumulated since: the `migrate` CLI's three pipeline stages (`analyze`/`transform`/`verify`) for porting an ACP agent onto the A2A shell, a malformed-request-body fix, SSE reconnect support, an Agent Card emitter CLI, `SendMessage` content negotiation/history-length/reference-task handling, and the `SkillResult` status-vocabulary and metadata-content-type fixes below. It also carries forward, as its ACP-line baseline, fixes shipped on the `1.x` line after this branch diverged: a `KnowledgeTool` routing-prefix rename, a fail-closed behavior change for a tool with no backend, and configurable per-tool MCP call timeouts.

Version line: `2.0.0` is a breaking change from the `1.x` ACP line (ACP surface removed, A2A JSON-RPC surface added). See the versioning and support page in the documentation.

### Removed
- **`MemoryTool` (`ctx.tools.memory.*`) is deleted.** It routed through the MCP Gateway, which never had a matching backend ("tool not found"), and there were zero production consumers. `MemoryClient` (direct HTTP to the memory service) is, and remains, the canonical path.

### Added
- `HITLTool.requires_write_hitl(tool_fqn)` — a synchronous, no-network classification of whether a specific MCP tool call is likely to need write approval, mirroring the TypeScript agent SDK's `requiresWriteHitl` and the platform's own Gate A classifier. Lets a skill decide up front whether to build a pause before calling a write-class tool, instead of guessing or hand-rolling a fail-then-recover loop.
- `AgentExecutionContext.mcp_write_hitl_active` — a coarse, run-level mint-time hint (does this run's token carry any write-capable `mcp:*` scope?), read from the platform's `execution_hints`. Always `False` for a service-account run, since an SA has no interactive HITL resume path.
- `ConnectorTool.call()` gains a `tier` argument (`"standard"` / `"licensed"` / `"ext"`, default `"standard"`) so licensed and third-party connectors are reachable through the SDK's governed surface. Licensed/ext-tier connectors are registered one segment longer than standard ones; previously, calling one through `ConnectorTool.call()` always built the standard-tier name and failed with tool-not-found. Backward-compatible: every existing caller, which never passes `tier`, is unaffected.
- 2.x documentation set: an A2A primer, a migration guide from 1.x, and a `migrate` CLI reference; guides updated to the A2A client and agent surfaces.
- **`python -m novaos_client_sdk.migrate verify` runs a migrated agent's own pre-migration fixtures against it and checks its Agent Card.** Where `analyze` only reads an agent's source and `transform` only rewrites it, `verify` is the pipeline stage that actually calls the migrated agent: it converts each fixture into the A2A `SendMessage` request an equivalent caller would send today, fires it at a live agent process over this SDK's own `Client`, and asserts the resulting `Task` reached the expected state. `--stream` also probes a skill with `SendStreamingMessage`, and an Agent Card check compares the agent's declared skills against its manifest in both directions.
- **`python -m novaos_client_sdk.migrate transform` mechanically rewrites an ACP agent onto the A2A shell**, using a lossless concrete-syntax-tree rewriter (not `ast`) so it can edit a file in place while preserving every comment and formatting choice elsewhere in it. It refuses rather than guesses when a migration plan is not eligible or contains an action with no handler, and a second run against an already-migrated file is a no-op (idempotent).
- **`python -m novaos_client_sdk.migrate analyze` classifies an ACP agent ahead of its A2A migration.** It determines which of three request-handling shapes an agent's server implements, surfaces every ACP-shaped construct in its source, and flags anything that would crash or silently misbehave after a mechanical port — all from pure source analysis; the target agent is never imported or executed. `--fleet` runs the same analysis over a directory of agents at once.
- **`AgentBuilder.handle_a2a_bytes()`/`handle_a2a_bytes_with_headers()` and `asgi_endpoint()` — a malformed request body now answers JSON-RPC `-32700`, not an HTTP 500.** Previously every entry point took an already-decoded body, so a pod route had to decode it itself before reaching the SDK, and invalid JSON there surfaced as an unhandled 500. `asgi_endpoint()` returns a ready-made ASGI callable that dispatches `SendStreamingMessage`/`SubscribeToTask` to an SSE response and everything else to JSON, so a template's entire A2A route collapses to one line.
- **`GatewayClient.events()` can now resume a dropped SSE connection, and `events_with_reconnect()` does it automatically.** `StreamEvent` gains an `id` field carrying the SSE event id; `events()` gains a `last_event_id` argument. `events_with_reconnect()` tracks the last id seen and reconnects on a retryable disconnect with exponential backoff; a non-retryable error (e.g. an authentication failure) still propagates immediately.
- **`python -m novaos_client_sdk.agent_card` emits a live agent's Agent Card as JSON**, so tooling outside the Python process (a CLI publish step, an activation pipeline) can read it without hand-rolling the shape. Exits non-zero with a one-line reason on stderr for a bad module, a missing attribute, or an attribute that isn't an `AgentBuilder`.
- **`AgentBuilder` now negotiates content types server-side, honours `SendMessage`'s nested `historyLength`, and resolves `referenceTaskIds`.** A `SendMessage`/`SendStreamingMessage` whose accepted output modes share nothing with the resolved skill's supported modes now answers a request-level `ContentTypeNotSupportedError` (`-32005`) before any task is created or persisted. `configuration.historyLength` now bounds `Task.history` on `SendMessage`/`SendStreamingMessage` themselves, not just `GetTask`/`ListTasks`. **Behaviour change:** a `SendMessage`/`SendStreamingMessage` naming a still-open task's id now accumulates onto that task's stored history instead of resetting it — fixing a gap that silently discarded the turn a paused `INPUT_REQUIRED`/`AUTH_REQUIRED` task exists to let a caller answer.
- **A dedicated "Agent memory" guide** (`docs/public/guides/memory.md`) covering both doors to Memory Service — `ctx.memory.client()` (direct) and `ctx.tools.memory` (through the MCP Gateway) — with a comparison of when to use which, the id table, write idempotency, pre-fetched context, degradation-state fields, and consistency guarantees.
- **`ctx.tools.memory` is back: `ToolBindings.memory` (`MemoryTool`) with `write()` and `query()`**, calling the real `novaos.memory.write` / `novaos.memory.query` MCP Gateway tools. This is a new binding, not a revival of the one `2.0.0` deleted (which targeted Gateway tools with no backend). It is governed like every other `ctx.tools` binding — Gateway policy, audit, metering and `tool.call`/`tool.result` stream events — and needs `mcp:tools:memory` (or `mcp:tools:*`) on the execution token in addition to `memory:*` scopes.
- **Memory pre-fetch before a skill runs.** When the platform attaches a `memory_budget` to a request (it does for agents that declare `memory` in `permissions.tools`), `AgentBuilder` calls `assemble_context()` once per turn before the skill handler starts and exposes the result as `ctx.memory.context`; `ctx.memory_budget` exposes the budget itself. A pre-fetch failure is logged and never fails the turn. Each successful pre-fetch emits a `memory.assembled` platform event — as a `WORKING` status frame on streaming requests, and folded into the terminal message's platform metadata part on non-streaming ones. `ctx.memory` is now cached per execution so the pre-fetched value is visible to the skill.
- **`MemoryClient.hint()` defaults `conversation_id` from `ctx.context_id`, `assemble_context()` defaults `request_id`/`trace_id` from `ctx.run_id`/`ctx.trace_id` (it takes no `conversation_id` — Memory Service scopes live messages from the token), and `write()` defaults its idempotency key from `ctx.idempotency_key` plus a per-execution ordinal**, when a `ctx` is passed. The ordinal is tracked on `ctx` itself (not on the `MemoryClient` instance, which is typically constructed fresh per call), so repeated writes across one execution get distinct, stable keys instead of a fresh random UUID every time. Backward-compatible: `ctx` is optional and explicit arguments still override the derived defaults.

### Changed
- Removed internal ticket, decision-record, repository and customer references from shipped docstrings, comments and CLI help; no behaviour change.

### Fixed
- **BREAKING: `SkillResult.status` outside the known vocabulary no longer silently maps to `TASK_STATE_COMPLETED`.** Four legacy spellings (`QUEUED`, `RUNNING`, `IN_PROGRESS`, `ERROR`) are now mapped to the A2A state they always meant; anything still outside the vocabulary now fails the task as `TASK_STATE_FAILED`, with the bad value named in both an error-level log and the task's own status message. **Behaviour change:** an agent relying on the old silent-`COMPLETED` fallback for an out-of-vocabulary status now gets a failed task instead. A skill returning `QUEUED`/`RUNNING`/`IN_PROGRESS` for a non-idempotent effect should deduplicate on `ctx.idempotency_key`, since these states are not in `INTERRUPT_TASK_STATES` and a caller cannot distinguish a deliberate open task from a dropped connection.
- **A skill's own `SkillResult.metadata` no longer collides with platform metadata on the wire, so it reaches the run-artifacts API.** It was previously folded into a `DataPart` tagged with the same content-type the platform uses for its own internal metadata, so the platform's event pipeline silently excluded it from caller-visible run data. A new `NOVAOS_SKILL_METADATA_CONTENT_TYPE` marks a skill's own folded-in result distinctly. **Wire-shape change:** an agent's `SkillResult.metadata` is now carried in a `DataPart` tagged a different content-type than before — a minor-version-bump-worthy change.
- **`AgentExecutionContext.trace_id` now carries the bare W3C trace id, not the whole `traceparent` header.** It previously stored the full header string, so anything correlating on the trace id alone — logs, spans, downstream lookups — never matched. The raw header is available as a new `traceparent` field for propagation, and tool-call spans now also carry `novaos.run_id`. **Behaviour change:** code reading `trace_id` and expecting a `00-<trace>-<span>-01` string should read `traceparent` instead.
- **`MemoryClient(max_retries=0)` now issues one attempt instead of none.** Previously the retry loop ranged directly over `max_retries`, so `0` skipped the loop body entirely — the only place that calls the memory service — and the method raised a `TypeError` from an unset error variable instead of ever reaching the service or surfacing its real response. `max_retries=0` now means "no retries", matching its documented intent, not "no attempts": the one attempt still runs, and its real error (or result) is what a caller sees on failure.
